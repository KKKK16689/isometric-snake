# isometric-snake 3.0 · Stage 3 设计简报（层图 AI）

> 依据：用户规格 §5「AI 契约」＋ §6「Stage 3」；现状锚点见文末「代码坐标」。
> 本文件只做设计，不含实现；Stage 3 的代码等用户确认后开工。

## 1. 目标与验收（照规格 §6）
- 把 AI 的搜索从「经典正方形网格」搬到**层图**上：节点 `(x,y,L)`，边由 §3.3 选层规则生成，权重 1。
- 传送门作为边（`terrain.neighbors()` 已经加了这条边 ⇒ `reachable()` 与 AI 必须共用同一套邻接，避免「AI 认为能走、实际不能走」）。
- 冲刺竞速按速度折算（规格 §5：冲刺 1 格/tick、常速 0.5 格/tick），不要只比格距。
- **验收**：三张图（test-24 / harbor-32 / ridges-40）各 500 局，0 非法移动、0 撞悬崖、0 卡死。

## 2. 现状（`src/js/ai.js`，v2 算法）
- `cellKey(x,y) = x*1024 + y`（**不含层号**）；`free(x,y)` 用 `x/y ∈ [0,S.N)` 判边界。
- 单次多源 BFS：`bfs(sources, withDist)` —— 以全部食物为源得距离场 `dist`，同时算连通域编号 `comp` 与面积 `size`。
- 评分：`roomy ? 1000 - min(fd,500) : area` 再减 `risky*60`；`roomy = area >= body.length + 3`。
- 残局：`moves.every(m => m.area < body.length + 3)` 时改追自己尾格。
- 冲刺竞速：先按 `lv.sprint && pick.fd <= lv.near && energy > minE && !locked` 决定想不想冲，再比对手 `ofd`，只有 `pick.fd < ofd` 才真冲（平局省能量）。
- 三档难度 `AI_LV`：easy `{err:.08, sprint:false}` / normal `{err:.02, near:6, minE:50}` / hard `{err:0, near:9, minE:30}`；`err` 是按比例随机走一步。
- 入口：`Snake.Ai = { init, think, setLevel, levels }`；`think(p, idx)` 被 core 在 `S.pl.forEach((p,i) => { if (p.ai && !p.dead && Snake.hooks.think) ... })` 里调用。

## 3. 改造点（保持零依赖、经典行为不变）
1. **键与邻接抽象**：新增内部 `nbr(x,y,L)` / `key(x,y,L)`：`S.T` 存在时走 `S.T.neighbors()/key()`（含传送门边），否则保留现有 `cellKey` + 四邻 + `free()` 语义 —— 经典模式的搜索路径**逐字不变**（这是「经典 AI 行为锁」能锁住的前提）。
2. **节点集合**：远征下 `nodes` 来自 `S.T.walkables()`（层图节点），而不是 `S.N×S.N` 网格；食物按 `(x,y,L)` 参与 BFS 源。
3. **冲刺折算**：把「格距」换成「时间」——`eta = fd * (sprint ? 1 : 2) tick`，对手同理；只在 `eta < oppEta` 时冲刺。经典模式下两者速度一致，折算后退化为原判据（可断言等价）。
4. **残局尾追**：尾格改为「自己最后一节的 `(x,y,L)`」；追尾评分保留 `1000 - 曼哈顿距离`，层图下曼哈顿距离改用层图 BFS 距离（同一张 `dist` 场换成以尾格为源）。
5. **`err` 随机**：在层图上按候选数量抽样，保持「按比例随机走一步」的语义；远征节点多，`err` 不放大。
6. **不改**：AI 难度参数、`think` 的调用契约、`ai` 模式的玩法与手感。

## 4. 回归护栏（Stage 3 的「不加坏」保证）
- 现有「困难 AI 对随机策略胜率 ≥ 85%（200 局）」继续留着。
- 新增**经典 AI 行为锁**：定种子 + `setLevel(2)` + 固定对局数，把「每局步数/得分/结束原因」混成摘要钉住 —— 一旦 Stage 3 动了经典搜索路径，摘要立刻变红。
- 新增**远征 AI soak**：三张图各 500 局（AI 自走、`S.pl[0].ai = true`），逐帧断言：① 每节都在可行走层；② 没有一步落在悬崖/墙/水上（撞了只能是别的原因）；③ 连续 200 tick 无位移且未结束 ⇒ 判「卡死」；④ 食物始终在该格最高可走层。
- 跑得动：40×40 层图 1600 节点，一次多源 BFS ≈几千次入队，每 tick 一次在该量级下完全可接受（现有远征渲染每帧 1500 条绘制指令都比它贵）。

## 5. 需要你拍板的三件事
- **Q1 远征的 AI 怎么用？**
  A（推荐）**只在测试里驱动** —— 不动玩法入口，先把算法打磨稳；远征保持单人。
  B 加 `?ai=1` 让 AI 陪玩/自动演示 —— 多一个 URL 参数与一条玩法分支，得在 Stage 4/5 一起定观感。
- **Q2 要不要「经典 AI 行为锁」？**（推荐要：Stage 3 是唯一会碰到经典 ai 模式搜索路径的阶段，锁住最省心。）
- **Q3 500 局验收的「卡死」口径**（推荐：连续 200 tick 无位移且 `state==='playing'`）。

## 6. 风险
- 层图邻接若与 core 的落点规则出现第二套实现，就会「AI 认为能走、实际撞死」⇒ 一律走 `terrain.pick()` / `terrain.neighbors()` 单一来源（core 已是这么用的）。
- 冰面（§5 提到的 transition 前置）未实现前，AI **不进冰原**：`I/L` 目前是 `layersOf()` 抛错的占位符，Stage 4 做完冰面再放开。
- 追尾在多层地形上可能来回上下台阶 ⇒ 验收时看「局均步数」而不是只看胜率。

## 7. 代码坐标（改前锚点）
