## 2. 先做 Stage 0：清晰度修复（独立提交，不混地形）
根因：canvas backing store 始终按逻辑 S.W*dpr 计算，CSS 尺寸却是容器宽度；body.im 下 1024px 屏幕只有 1120px 背店，等效 1.09x；dpr 被硬顶在 2。
要求：
1. fitCanvas 先确定 CSS 尺寸；随后测量 canvas 的 getBoundingClientRect()。
2. dprEff = max(1, min(devicePixelRatio, 3, sqrt(MAX_PIXELS/(cssW*cssH))))；MAX_PIXELS 移动端 4.5e6、桌面 8e6；不要固定 2。
3. cv.width = round(cssW*dprEff)，cv.height = round(cssH*dprEff)。
4. 逻辑坐标仍用 S.W/S.H；ctx.setTransform(dprEff*k, 0, 0, dprEff*k, 0, 0)，k = cssW/S.W；fitCanvas 已保证比例。
5. boardCache 按新 backing 尺寸重建；glowCache 与 vignette 清空重建。
6. 静态地板/网格顶点对齐设备像素：snap(v)=Math.round(v*dprEff*k)/(dprEff*k)；蛇的插值坐标不要取整，否则会抖。
7. 网格线宽用 1/k（保持 1 CSS px）；辉光精灵按 dprEff*k 生成并缓存，不要用低分辨率精灵放大。
8. 监听 resize / orientationchange / visualViewport resize / ResizeObserver(main)；rect 为 0 时回退 S.W。
9. 保留蛇头/食物辉光；身体光晕在 lowFx 关闭，正常模式可降 alpha，不要直接删美术。
验收：1024×768@2、390×844@3、1920×1080@1 下 canvas.width 与 rect.width*dprEff 误差 ≤1；横屏 PK 正常；FPS 不低于 2.0 的 90%。
只做这一阶段，提交后停下。

## 3. 地形数据契约（先写 docs/terrain-spec.md，再写代码）

### 3.1 层，而不是“格子类型 + 高度”
每个格子有 1~2 个 layer，每层包含：h(0..3)、walkable、kind(ground/deck/water/lava/wall/ice/portal...)、视觉属性。
桥 = 同一格 ground + deck 两层；禁止用单个 cell.height 表示桥。

### 3.2 蛇身与食物带层号
body segment = {x,y,L}；food/gold = {x,y,L}；碰撞、吃食、占位只比较同 (x,y,L)。
允许蛇在高架上跨过自己在地面的身体；桥下的蛇不被桥上的身体挡住。

### 3.3 移动规则
从 (x,y,L) 到相邻 (nx,ny)：
- 在目标格的可走层中，选 |h - 当前层 h| 最小的一层；同差值优先同层，其次较高层。
- 最小差值 > 1 → 不可走（悬崖 = 墙）。
- 目标层 walkable=false → 不可走。
- 桥下通行由“按层选”自然成立，不要写特判。
- 台阶/坡道由相邻层高差 1 自然产生，不新增斜坡类型。
- 高度只影响可走性，不改变 tick 速度、冲刺、连击。

### 3.4 传送门
- 传送门是层图上的双向边，不是“瞬移到另一格”的特判。
- 两端必须是 walkable 层；落地层必须可走；成对由字母定义（P/p、Q/q）。
- 蛇身按路径逐 tick 穿过，允许路径在地图上不连续；渲染在两端画门的光效。

### 3.5 食物与金苹果
- 只在“该格最高可走层”生成；桥下的地面层不生成，避免看不见但吃不到。
- 生成前检查从任一蛇头所在层可达；不可达的层不生成。

### 3.6 ASCII 地图
用 src/js/levels.js 里的模板字符串，build 直接内联，保持零依赖：
- `.` 平地 h0
- `1/2/3` 可走高台 h1/2/3
- `#` 墙（不可走，视觉 h3）
- `~` 水（不可走，h0）
- `B` 桥面 h2 + 下方水（不可走）
- `b` 桥面 h2 + 下方平地 h0（可桥下通行）
- `P/p`、`Q/q` 成对传送门
- `@` P1 出生点，`$` P2 出生点
- `I` 冰、`L` 熔岩：先保留字符，Stage 4 再实现
每行等长、四周有墙；出生点要有 3 格直线跑道；每个 walkable 层节点从出生点可达；传送门成对且两端可走。
validateLevel() 必须对不合法地图抛错，禁止静默补齐。

### 3.7 关卡、模式与存档版本
- 3.0 新键前缀 iso-snake-3:，不迁移也不覆盖 2.0 的 best/ghost/stats。
- 地形只进入新模式 expedition；经典模式保持 2.0 规则。
- 新 ghost/每日记录必须带 levelId + rulesetVersion；地图不匹配的 ghost 不显示。
- 每个关卡：id、名称、biome、地图尺寸、食物数量、出生方向、规则版本。

## 4. 渲染与相机契约
- 拆 S.MAP_N（24）与 S.VIEW_N（视口格数：桌面 18、手机 14）；S.W/S.H 只由 VIEW_N 派生；遍历地图用 MAP_N，投影/画布用 VIEW_N。禁止再用 S.N 同时表示两者。
- 相机跟随蛇头，死区 2 格，边界 clamp；传送时 snap；reduced-motion 时直接 snap。
- 相机偏移取整到设备像素；静态缓存比视口多 2 格 margin，超出 margin 才重建；不要每帧重绘全图。
- 只绘制视口 + 1 格 margin；不可见格不参与 items。
- 会遮挡蛇的高地形（墙/高台/桥面）禁止进静态地板缓存，必须进动态 items 深度排序。
- 深度排序键：x+y → layer（低层先）→ 类型（地形先，实体后）。同一格先画 deck，再画 deck 上的蛇；桥下的蛇由 deck 后画覆盖。
- 被遮挡的蛇：只在遮挡发生时，在最后叠加蛇头 + 前 2 节的半透明轮廓；不要给全蛇描边。
- 小地图：独立小 canvas，4~8Hz 更新；画地图轮廓、玩家、食物、视口框；不要每帧重绘。
- PK 保持全景固定视角，不用跟随相机；只有单人 expedition 用相机。
- 桥面下方画支柱/阴影，避免“悬浮平台”错觉。

## 5. AI 契约
- 图节点 (x,y,L)，边由移动规则生成，权重 1；多源 BFS 到食物；连通域面积按节点统计；尾追也在层图上做。
- 占位 key 从 (x,y) 改为 (x,y,L)；不同层互不阻挡。
- 传送门作为边，不做瞬移特判。
- 金苹果加入目标；冲刺竞速按双方速度折算（冲刺 1 格/tick，常速 0.5 格/tick），不要只比格距。
- 冰面会让“一步落点”不是相邻格：先实现 transition 函数，再在冰原启用 AI；否则冰原禁用 AI。
- 保留 AI_LV 难度参数；用无头批量对局验证新地图下无非法移动、无撞悬崖、无卡死。

## 9. Stage 0 实施记录（2026-10-25，已完成待验收）
- 改动文件：`src/js/render.js`（唯一逻辑改动）、`test/integration.test.mjs`（桩 + 断言 + 新增用例）、`index.html`（`node build.js` 产物）。
- 关键实现：
  - 删除 `const dpr = Math.min(devicePixelRatio || 1, 2)`；新增 `MAX_PX_DESKTOP 8e6` / `MAX_PX_MOBILE 4.5e6`、`scale`、`cssK`、`snap()`。
  - `applyCanvasSize()`：先 `fitCanvas()` 定 CSS 尺寸 → `getBoundingClientRect()` 实测（rect 为 0 回退 `S.W/S.H`）→ `dprEff = max(1, min(devicePixelRatio, 3, sqrt(预算/面积)))` → **背店 = round(css × dprEff)** → `cssK = cssW/S.W`、`scale = dprEff × cssK` → `setTransform(scale,…)` → boardCache / vignette / glowCache 全部重建；尺寸与比例都没变则提前返回（resize 抖动不重建缓存）。
  - 静态地板/网格：台缘顶点与瓦片中心全部 `snap()` 对齐设备像素（蛇插值坐标不取整，避免抖动）；网格/倒角/台缘线宽改 `1/cssK`（恒 1 CSS px）。
  - 辉光精灵：按 `ceil(64 × scale)` 生成（上限 256px）并缓存，替换“32px 低分精灵放大”；scale 变化时清空缓存。
  - 事件：bus `resize` + window `resize` + `orientationchange` + `visualViewport.resize` + `ResizeObserver(main)`；`Snake.Render.refit` 改指向 `applyCanvasSize`（全屏切换走同一条路）。
  - 美术：身体鳞片光晕 alpha `.10/.05 → .07/.035`（边缘更实）；蛇头/食物/金苹果辉光在 lowFx 下也保留。
- 测试：`node --test` → **26/26 全绿**（原 25 + 新增 Stage 0 用例）。新用例覆盖 4 组设备档、3x 不再被硬顶、与旧公式对比、orientationchange / visualViewport / ResizeObserver 重建、rect 全 0 兜底；原 `cv.width === S.W*2` 断言改为按 `rect × dprEff` 断言。`node build.js` 产物 99.3KB 且二次构建哈希一致。

  | 1024×768 @2 | 经典 | 1024×609 | 760×452 | 0.74x | 2048×1218 | 2.00x |
