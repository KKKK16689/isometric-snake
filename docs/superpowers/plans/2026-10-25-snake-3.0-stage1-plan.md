> 写给用户的一页纸：把 `docs/terrain-spec.md` §9 的 5 个问题变成「选项 / 代价 / 推荐」，并把 Stage 1 的

## 0. 为什么先给图、不先写代码

Stage 1 的验收句是「24×24 测试图可玩经典规则，画面正确，遮挡正确」。这句话要能验收，前提是**有一张
合法且覆盖全部形状的图**。所以先把图做出来并验过，等答复一到就能直接进实现，不用边写边猜图。
校验器是仓库外的参考实现（`D:\snake3-qa\level-check.mjs`）：它按 §3.3 的移动规则建层图、按 §3.6 的图例
解析，跑 8 项检查，并带 4 个反向用例证明它「不是恒过」。Stage 1 落地时，这套语义会直接变成
`terrain.js` + `test/terrain.test.mjs`（检查项一一对应），不会出现「文档一套、代码一套」。

## 1. 决策简报：5 问 → 选项 / 代价 / 推荐

**Q1 测试图用灰模还是霓虹都市？**
- 关键事实：**地图数据与皮肤无关**。第 2 节那张图既能当灰模，也能当霓虹都市——皮肤只影响调色板与
  地板图案注册表（`themes.js` / `patterns.js`），不影响层图、碰撞、验收项。
- A 灰模（`#` 灰块 / `~` 蓝灰水面 / `b`、`B` 石板桥）：遮挡与深度排序最容易一眼看出对错 ✅
- B 直接上霓虹皮肤：观感好，但同时引入美术变量，遮挡错了不容易判断是排序错还是美术错 ⚠️
- **推荐 A**：Stage 1 判「遮挡正确」，灰模最省事；皮肤留到 Stage 4 的 biome 阶段。

**Q2 经典模式是否保持老渲染路径？**
- A 完全共用：经典模式也走层图渲染，只是它的图没有高差/桥/传送门（全部 layer 0）
- B 分叉：经典走旧渲染、expedition 走新渲染
- 代价：B 等于长期维护两套渲染器，且 Stage 2–4 每次改渲染都要同步两遍；A 的风险是经典画面被连带改动，
  但**已经有护栏**：行为锁（1200 tick 状态摘要）、视觉锁（两个种子的绘制轨迹摘要）、渲染成本护栏
  （每帧绘制量预算）。三锁任一变红就说明经典被动过，立刻回滚。
- **推荐 A**（经典视觉锁保持不变是 Stage 1 的硬验收项）。

**Q3 新模式（expedition）入口放哪？**
- 现状：工具栏已有 12 个控件 + 1 个 select，沉浸态单行排布约 780px；窄屏已有换行兜底，但余量不多
  （此前修过两次重叠）。
- A 工具栏再加一个「远征」按钮 ⚠️ 窄屏换行/重叠风险重现
- B 复用模式按钮区加第 5 个模式 ⚠️ 同上，且模式区语义会变挤
- C 先用 URL `?mode=expedition&level=<id>` 直达，工具栏不动 ✅ Stage 1 验收完全够用
- **推荐 C**；等 Stage 4 场景齐了再讨论正式入口（那时可以做一个模式选择面板，而不是继续往工具栏塞）。

**Q4 小地图放哪？**
- A 画布右下角内嵌 ⚠️ 沉浸态右下是方向垫（132px 宽）
- B 画布左下角 ⚠️ `?fps=1` 诊断读数就在左下（可以让位，但两个都不该抢玩家的视线）
- C 挂在 HUD 一侧的独立小 canvas（单人沉浸时 `#hr` 那侧是空的）✅ 不占画布、不参与每帧重绘
- **推荐 C**（4~8Hz 更新，独立 canvas）。

**Q5 桥面支柱怎么画？**
- A 两根斜柱 + 投影（等距感最强，绘制量小：只有桥面格）✅
- B 一根中柱 + 阴影（更省）
- C 只画投影不画柱（最省，但容易像"悬浮平台"）
- **推荐 A**。

> 最小回复：**「都按推荐」** 四个字即可；不同意的写编号（例如「Q3 选 B」）。

校验报告（参考校验器输出）：
- 尺寸 24×24，层节点 **596** 个，可行走 **457** 个（ground 433 · wall 112 · water 27 · deck 20 · portal 4）
- P1 出生点 (2,11)、P2 出生点 (21,6)，两人各有一条 3 格直线跑道
- 传送门两组都在（P(2,2)↔p(21,3)、Q(21,20)↔q(2,21)），两端所在层均可走
- 8 项检查全过：行等长 / 四周封闭 / 出生点唯一 / 3 格跑道 / 全部可走层节点从出生点可达 /
  传送门配对 / 桥的上下层关系 / 每格 ≤ 2 层
- 4 个反向用例都被正确捕获（行不等长、传送门落单、出生点无跑道、孤岛不可达）⇒ 校验器不是恒过

**这张图专门覆盖 Stage 1–2 要验收的形状**：h2 台面 + h1 台阶（Δh ≤ 1 才能上）、跨水桥 `B`（两端必须有
h1 引桥，否则 Δh=2 上不去——这正是「台阶由高差自然产生」的验证点）、跨地平桥 `b`（桥下地面保持可走，
用来验证「按层选层」让蛇从桥下穿过）、墙块（遮挡与深度排序）、两对传送门（层图上的双向边，不是瞬移特判）。

## 3. Stage 1 实施方案（答复到位后按此执行，仍是一个提交、做完停下汇报）

**新增**
- `src/js/terrain.js`：图例解析 → 层图；`validateLevel(rows)`（不合法即抛错，绝不静默补齐）；
  层图 API：`nodesAt(x,y)` / `neighbors(x,y,L)`（§3.3 选层规则）/ `pickTargetLayer(...)`。
  纯数据、不碰 DOM/CSS，所以能进无头测试。
- `src/js/levels.js`：关卡注册表（`id` / `name` / `biome` / 地图 / 食物数 / 出生朝向 / `rulesetVersion`），
  先只放第 2 节这一张。
- `test/terrain.test.mjs`：解析、8 项校验、选层规则、传送门边、可达性、4 个负例（必须抛错）。

**改动**
- `src/js/core.js`：拆 `S.MAP_N = 24` 与 `S.VIEW_N`（桌面 18 / 手机 14）；`S.W/S.H` 改为由 `VIEW_N` 派生；
  `setSize()` 与新常量接线；`body` 段加 `L` 层号（经典模式恒为 0，行为不变）；碰撞**只加「目标层不可走」
  硬阻挡**（Stage 1 按 §6 不加高差/桥/传送门规则）。
  已核的 9 处 `S.N` 触点：`core.js:96`(setSize)、`core.js:128`(出生点)、`core.js:140`/`:152`(fillFoods)、
  `core.js:219`(撞墙)、`ai.js:24`(BFS 边界)、`ai.js:47`(连通域补标)、`render.js:112`(台缘)、`render.js:115`(瓦片遍历)
  ——逐处改成「地图尺寸 / 视口尺寸」各自正确的语义。
- `src/js/render.js`：静态地板缓存按「视口 + 2 格 margin」重建（沿用现有 `boardCache` 机制，只改重建触发与
  绘制范围）；遍历用 `MAP_N`、投影与画布用 `VIEW_N`；相机跟随（死区 2 格、边界 clamp、`reduced-motion`
  直接 snap、偏移取整到设备像素 ⇒ 静态层不抖）；深度排序键 `x+y → layer → 类型`（在现有 `items` 排序上扩展）；
  **会遮挡蛇的高地形（墙 / 高台 / 桥面）不进静态缓存**，必须走动态 items；小地图独立 canvas，4~8Hz。

**Stage 1 验收（照 §6）**
1. 第 2 节那张图能用经典规则跑通（只有墙/水的硬阻挡，不进高差与传送门规则）；
2. 画面正确、遮挡正确（桥下蛇被桥面盖住、桥上蛇跨过地面身体）；
3. `node --test` 全绿（含新增 terrain 用例）；
4. `node build.js` 仍产出单文件、可双击运行；
5. **三道经典护栏保持不变**（行为锁摘要 `0xe692ec99`；视觉锁两个种子摘要 `0xe88121c2` / `0x90df7f42`；
   若 Stage 1 让视觉锁变红，说明经典渲染路径被动过 ⇒ 按规格 §7 回滚，而不是改摘要）；
6. 完成后停下汇报（改了哪些文件、diff 摘要、测试命令与结果、已知风险、下一步建议）。

**回滚**：Stage 1 收在一个提交里；`git revert <sha>` 或退回 `tag v2.0.0`（2.0 基线）。
未验收前不推送、不发 Release、不动线上 Pages。

## 4. 与其它阶段的边界（防止顺手做过头）

- 不在 Stage 1 做：高差规则、桥下通行规则、传送门规则（Stage 2）、层图 AI（Stage 3）、biome 皮肤与机关（Stage 4）。
- 数据结构一次到位（层/桥/传送门字段都留好），但**规则**按阶段开：Stage 1 只认「不可走就是墙」。
