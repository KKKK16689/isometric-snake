# Stage 4 · 最后一个 biome：太空站（周期机关 + 移动平台）实施计划

> 依据：用户规格 §6「最后冰原/熔岩/太空站（滑行/周期机关/移动平台），一次只加一个 biome」＋ §5「冰面会让一步落点不是相邻格 ⇒ 先实现 transition 函数再让 AI 上冰」的同一条思路。
> 现状（可核验）：`HEAD=2ac21d1`、64/64 绿、build 166.8KB；已完成的 biome：grey / neon / ruins / lava / ice（冰面滑行已接进玩法并给 AI 加了门控）。

## 0. 核心设计取舍（为什么先做闸门、后做平台）
- 层图（`terrain.js`）是**静态**的：`pick()` 只按层高选落点。任何「随时间变化」的东西都不能直接塞进静态层图，否则 AI、校验、存档全要跟着变。
- **周期闸门**只需要「某一格此刻算不算墙」这一位信息 ⇒ 层图不变，`core` 的 `solid/pick` 查一次 `gateOpen(t)` 即可；AI 的 `free()` 也查同一个函数就能立刻正确。**代价最小、收益最直观**。
- **移动平台**会改变格子高度 ⇒ 站在上面的蛇要被「载着走」，`pick()` 得看当前高度，涉及搬运/相对位移/相机与渲染的抬升同步 ⇒ 属于第二步，等闸门稳定后再动。
- 结论：**先闸门（本轮）→ 平台（下一轮）**；每次只上一个，做完各自停下汇报。

## 1. 数据与地图（levels.js）
- 新字符：`G` = 闸门格（默认关闭态由关卡数据给出相位）。`terrain.js` 的 `layersOf('G')` 返回 `[{ h: 0, walkable: true, kind: 'gate' }]`（**层图里仍可走**；是否真能走由运行时相位决定）。
- 关卡对象新增字段：`gates: [{ x, y, period, phase }]`（毫秒；`open(t) = ((t + phase) % period) < period / 2`）。缺省 period 4000 / phase 0。
- `validate()` 增检查：闸门必须在可走层上、不能压在出生点/传送门/食物常驻格上、`period ≥ 1200`（太快的闸门在 150ms 一格的节奏下等于随机致死）。
- 太空站 `station-32`（32×32）布局草案：外圈环形走廊 + 中央反应堆方块（墙）+ 3 道闸门卡在走廊收窄处 + 2 对传送门 + 出生点分居左上/右下（各垫 h1 落台，遵守「台地地图必须给出生点垫落台」的既有教训）。

## 2. 运行时（core.js）
- 每 tick 计算一次 `S.gateOn(x, y)`（或预计算成一个小 Set，避免每格重复取模）：关闭 ⇒ 该格按**墙**处理。
- 落点判定：`pick()` 命中的层 `kind === 'gate'` 且此刻关闭 ⇒ 视为撞墙（`bad: true`，与撞墙同一条判负路径，音效/粒子/震屏沿用）。
- **站在闸门里、闸门要关**：见 §4 待拍板问题 ①（推荐「安全闸」：不致死，闸门延后到蛇离开再关）。
- AI：`free(x,y,L)` 增 `&& gateOpenNow(x,y)`；关闭态格子对 AI 就是墙 ⇒ 无需改 BFS 结构。
- 存档：闸门相位随关卡数据走（不是随机）⇒ 幽灵/每日记录不受影响；`rulesetVersion` +1（规则变了）。

## 3. 渲染（render.js）
- 闸门格静态画法（进静态层，零逐帧成本）：门框两条立柱 + 地面轨道菱形；**动态**部分只有「能量帘」——按相位插值高度/透明度的一条亮带（加法通道里画一条，成本极低）。
- 关闭 ⇒ 帘满高、发亮；开启 ⇒ 帘收进地面、只留轨道。配 `BIOMES.station` 配色（冷灰金属 + 青色能量条 `strip: '#7FD4FF'` 之类）。
- 与冰面同样的原则：**一眼可辨**（用户对冰面的反馈就是这么来的）。

## 4. 待用户拍板的三个问题（推荐值已给，等你一句话）
1. **站在正在关闭的闸门里怎么办？** 推荐「安全闸」：不致死，闸门保持开启直到蛇离开（对玩家友好，也不会出现「明明没动却死了」的怪事）。备选：按撞墙判负（硬核，但反馈会很突兀）。
2. **移动平台载不载蛇？** 推荐「载着走」（平台移动时把蛇一起平移；被推到墙里则按撞墙判负）。备选：只做高度变化、不搬运（实现简单，但会出现「平台从脚下滑走」的怪感）。
3. **要不要无重力/传送带这类额外机关？** 推荐**不做**（列入非目标）：先把闸门与平台做扎实，避免一次加太多变量把难度与 AI 一起搞乱。

## 5. 验收与提交口径
- 单测：闸门相位函数（`open(t)` 边界值）、关闭态不可进入（撞墙判负）、站立时关闭的处理（按 ① 的裁决）、AI 在关闭态视为墙、`validate` 的三条新检查。
- AI 批量对局：`station-32` 500 局 0 非法移动 / 0 撞闸门 / 0 卡死（沿用 `SOAK_GAMES` 那套）。
- 三道经典锁必须全绿（行为摘要 / 视觉摘要 / 渲染成本），变红就回滚而不是改摘要。
- 提交拆分：`feat(stage4): 太空站——周期闸门（数据 + 运行时 + 美术 + 单测）`；平台另起一个提交。
