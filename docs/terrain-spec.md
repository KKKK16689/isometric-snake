# 3.0 地形数据契约（草案 · 待用户确认）

> 状态：**草案**。只写文档，未改任何游戏代码。依据＝用户的 3.0 规格
> （`docs/superpowers/plans/2026-10-25-snake-3.0-terrain-plan.md` §3–§5、§6 Stage 1）＋ 对 2.0 代码的实测侦察。
> 标「建议」的都是我的取舍，标「待确认」的必须你拍板后才动代码。

## 1. 数据结构：层图，不用「格子类型 + 高度」

```js
// 一个格子的每一层（格内按 h 升序排列，下标 0 是最低层）
{ h: 0, kind: 'ground', walkable: true, portal: null }   // kind: ground|deck|water|lava|wall|ice|portal
```

- **桥 = 同一格两层**（ground 在下、deck 在上），禁止用单个 `cell.height` 表示桥。
- 关卡对象：`{ id, name, biome, w, h, cells, spawn, ruleset }`；`cells[x][y]` = 层数组。
- 关卡尺寸与视口解耦：地图 `MAP_N = 24`，视口 `VIEW_N`（桌面 18 / 手机 14），`S.W/S.H` 只由 `VIEW_N` 派生。

**Terrain API（建议签名）**

| 函数 | 语义 |
|---|---|
| `at(x, y)` | 该格层数组（越界返回 `null`） |
| `layerAt(x, y, h)` | 指定 h 的层（无则 `null`） |
| `pick(x, y, fromH)` | 按 §3.3 规则选落点层：`{ h, dh, walkable }`；最小 `dh > 1` 或目标不可走 → `null` |
| `neighbors(x, y, L)` | 相邻格＋同格其它层＋传送门边，返回 `[{x,y,L,cost:1,portal:bool}]` |
| `key(x, y, L)` | 占位/访问标记键（取代现在的 `x*1024+y`） |
| `reachable(x, y, L, pred)` | 层图 BFS（食物可达性、连通域面积、AI 复用同一份） |
| `validate()` | 解析期校验，**不合法直接抛错，禁止静默补齐** |

## 2. 移动规则（照 §3.3 实现，不加特判）

从 `(x,y,L)` 到相邻 `(nx,ny)`：在目标格可走层中取 `|h - L.h|` 最小者；同差值优先同层、其次较高层；最小差值 `> 1` ＝ 悬崖不可走；目标层 `walkable=false` 不可走。
→ 桥下通行、台阶、坡道都由这条规则**自然产生**，不写 if。
→ 高度只影响可走性，**不改 tick 速度、冲刺、连击**。

## 3. ASCII 图例（`src/js/levels.js`，模板字符串内联）

| 字符 | 含义 |
|---|---|
| `.` | 平地 h0 |
| `1` `2` `3` | 可走高台 h1/h2/h3 |
| `#` | 墙（不可走，视觉 h3） |
| `~` | 水（不可走 h0） |
| `B` | 桥面 h2 + 下方水（不可走） |
| `b` | 桥面 h2 + 下方平地 h0（可桥下通行） |
| `P` `p`、`Q` `q` | 成对传送门（字母对） |
| `@` / `$` | P1 / P2 出生点 |
| `I` / `L` | 冰 / 熔岩（Stage 4 才实现，先保留字符） |

`validateLevel()` 抛错清单（每条都要有单测）：行数/每行等长、四周有墙、出生点存在且有 3 格直线跑道、每个可走层节点从出生点可达、传送门成对且两端可走、桥字符上下层关系正确、未实现的 `I/L` 出现在 Stage 4 之前要抛错。

## 5. 渲染与相机（§4 落地）

- `S.MAP_N = 24` / `S.VIEW_N = 18(桌面) | 14(手机)`；禁止再用 `S.N` 同时表示两者。
- 相机跟随蛇头、死区 2 格、边界 clamp、传送时 snap、`prefers-reduced-motion` 时全程 snap；相机偏移取整到设备像素。
- 静态地板缓存＝视口 + 2 格 margin，超出才重建（复用 Stage 0 的 `boardCache`/`invalidateBoard` 机制）。
- 只画视口 + 1 格 margin；**会遮挡蛇的高地形（墙/高台/桥面）不进静态缓存**，进动态 items。
- 深度排序键：`x+y → layer(低层先) → 类型(地形先、实体后)`；同格先画 deck 再画 deck 上的蛇；桥下的蛇被 deck 覆盖。
- 遮挡发生时才在最后补画「蛇头 + 前 2 节」的半透明轮廓，不给全蛇描边。
- 小地图：独立小 canvas，4~8Hz 更新（画轮廓/玩家/食物/视口框），不逐帧重绘。
- PK 保持全景固定视角；只有单人 expedition 用跟随相机。桥面下方画支柱/阴影，避免悬浮错觉。
- 位置：小地图放**画布右下角内侧**（建议；PK 与窄屏需避让方向垫）→ **待确认**。

## 6. AI（§5 落地）

- 节点 `(x,y,L)`，边由 `neighbors()` 生成，权重 1；多源 BFS 到食物；连通域面积按节点统计；尾追也在层图做。
- 冲刺竞速按速度折算：冲刺 1 格/tick、常速 0.5 格/tick（现在直接比格距 → 3.0 要改）。
- 冰面会让「一步落点」不是相邻格 → **先实现 transition 函数再开冰原 AI**，否则冰原禁用 AI。
- 保留 `AI_LV` 三档参数；用无头批量对局验证：无非法移动、无撞悬崖、无卡死（Stage 3 验收：3 张图 × 500 局）。

## 7. 存档与兼容（§3.7）

- 新键前缀 `iso-snake-3:`，**不迁移、不覆盖** 2.0 的 `iso-snake-best2-*` / `ghost` / `stats`。
- 地形只进新模式；经典模式规则不变。
- 新 ghost / 每日记录带 `levelId` + `rulesetVersion`；地图不匹配的 ghost 不显示（避免"对着别的图回放"）。
- 每个关卡声明：`id`、名称、biome、地图尺寸、食物数量、出生方向、规则版本。

## 10. 手感与性能红线（Stage 1-5 必须守住，均已作用例锁住）

1. **移动首帧必须画旧格**：`update(t)` 与 `draw(t)` 同帧同钟，移动那一帧 `t === moveT`（`a = 0`），此时若画新格会「瞬移一帧、下一帧再倒回起步」＝每格一次抖动。`segPos` 规定 `a ≤ 0 → 旧格`、`a ≥ 1 → 新格`。
2. **掉帧不补跑**：`update()` 一帧最多走一格，积压直接对齐当前时刻丢弃；补跑多步会让蛇在一帧里连跳好几格（用户原话：「不卡、没有瞬移就好」）。
3. **插值时钟语义**：`S.now` ＝渲染时钟（每帧写入），`p.moveT = S.now`；`p.moveTGame = S.last`（游戏时钟，供 `?interp=legacy` 复现 2.0 手感）。曲线：缓出 `ease(a) = 1-(1-a)^2.2`，`?span=0.5~1` 控制每格视觉到位占用一格时间的比例。
4. **背店分辨率**：`dprEff = max(qFloor, min(devicePixelRatio, 3, sqrt(budget/(cssW*cssH))) * qScale)`；`budget` 桌面 8e6 / 移动 4.5e6（粗指针或 min 边 < 600）；`qFloor` 在严重掉帧时可降到 `Q.softMin = .75`（dpr=1 的屏幕上没有它就没法降）。静态顶点 `snap()` 对齐设备像素，网格线宽 `1/cssK`，辉光精灵按 `scale` 生成。
5. **静态层不得逐帧重画**：地板缓存只在尺寸/主题/画质换档时重建；护栏＝地板缓存绘制量 < 主画布 30%、主画布 ≤ 700 条/帧（基线 326.9 条/帧）。
6. **相机（Stage 1）不得新增延迟**：相机偏移取整到设备像素、与蛇头用同一渲染时钟结算；跟随延迟必须为 0（死区只限制静止抖动，不得让画面滞后于输入）。
7. **诊断开关**：`?fps=1`（fps/帧时/画质%/lowFx/背店/漏帧率）、`?q=0.4~1`（固定画质倍率）、`?span=`、`?interp=legacy`。**A/B 必须同一次构建内对照**——跨运行的无头帧时数字不可比。
8. **测量工具**（仓库外 D:\snake3-qa）：`probe-server.mjs`（静态服务 + `/slow?ms=`）、`probe-inject.mjs`、`probe-ab.mjs`（带命中次数校验的变体补丁）、`probe-diag.mjs`（暴露 `window.__qlog`）、`probe-feel.mjs`（只读注入逐帧采样：调 `Snake.Render.segPos` 记录头部插值位置）+ `feel-parse.mjs`（解析 dump-dom 出对照表）；无头 Edge 用 `--headless=new … --dump-dom`，解析在 node 里做（PowerShell 解析内嵌 JSON 不可靠）。注意：`/slow?ms=` 的阻塞脚本必须放在采样脚本**之后**，否则采样脚本要等它下载完才开始跑。
9. **「跟手」有两个可测指标，缺一不可**：①**到达时间**（从移动开始到头部进入新格 95% 位置的毫秒数）②**起步瞬时位移**（第一帧的位移量；2.0 靠「起步抢跑」显得跟手，代价是瞬移）。**真浏览器实测（2560×1600@1、easy、9 格、60fps）**：3.0 默认缓出 **到达中位 169.9ms / 起步最大位移 0.333 格 / 位置倒退 0 次**；`?span=0.7` **121.2ms / 0.29 格 / 0 次**；`?interp=legacy` **163.7ms / 0.755 格**（起步跳得最多，因为跳幅 = 帧间隔/moveP，越清晰的大画布帧间隔越大 ⇒ legacy 在大屏上比 2.0 当年更跳）；真 2.0 **210.6ms / 0.222 格**。⇒ 默认档到达时间已比 2.0 早约 40ms，且完全没有倒退帧；嫌不够「冲」就用 `?span=0.7`（到达提前约 50ms，仍无倒退）。
